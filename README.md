# Hybrid RAG System

A local Hybrid Retrieval-Augmented Generation pipeline combining dense (embedding) search,
BM25 lexical search, and cross-encoder reranking, backed by a local LLM via Ollama.


## Project Structure

```
.
├── config/
│   └── config.py                # All tunable parameters
├── data/
│   ├── chroma_db/                 # Persistent vector store (auto-generated by build.py, not tracked in git)
│   └── dataset/                   # Place source PDFs here for ingestion
├── src/
│   ├── embeddings/
│   │   └── embedding.py           
│   ├── ingestion/
│   │   ├── clean.py               # PDF text extraction + cleaning (PyMuPDF)
│   │   ├── chunking.py            # Sentence-aware recursive chunking
│   │   ├── vector_store.py        # ChromaDB collection creation + storage
│   │   └── ingest.py              # Orchestrates: load -> chunk -> embed -> store
│   ├── retrieval/
│   │   ├── dense_retriever.py     # ChromaDB similarity search (returns raw distance)
│   │   ├── bm25_retriever.py      # BM25 lexical scoring
│   │   ├── hybrid_retriever.py    # Combines dense + BM25, applies distance-based filtering
│   │   └── pipeline.py            # Top-level retrieve() — full retrieval + rerank pipeline
│   ├── reranking/
│   │   └── reranker.py             # Cross-encoder scoring + score-threshold + top-k filtering
│   └── generation/
│       ├── prompt.py                # Grounded-answer prompt template
│       └── generator.py             # generate() — builds prompt and calls the local LLM
├── build.py                     # Entry point: runs all pre-retrieval work (ingestion/indexing)
├── main.py                      # Entry point: retrieval -> reranking -> generation (interactive loop)
├── requirements.txt
└── .gitignore
```

## How It Works

1. **`build.py`** — pre-retrieval work. Calls `src/ingestion/ingest.py`, which loads PDFs from
   `data/dataset/` (`clean.py`), splits them into overlapping sentence-based chunks
   (`chunking.py`), embeds them with a SentenceTransformer model (`src/embeddings/embedding.py`),
   and stores them in a persistent ChromaDB collection (`vector_store.py`).

2. **`main.py`** — everything from retrieval to generation, run interactively per query:
   - `src/retrieval/pipeline.py` runs dense vector search (`dense_retriever.py`) and BM25
     lexical scoring (`bm25_retriever.py`), combined in `hybrid_retriever.py`.
   - Results are filtered by a distance threshold, then reranked with a cross-encoder
     (`src/reranking/reranker.py`), filtered by rerank score, and cut to the configured top-k.
   - `src/generation/generator.py` builds a grounded prompt (`prompt.py`) from the final chunks
     and calls the local LLM via Ollama to produce the answer.


## Setup

```bash
pip install -r requirements.txt
python -c "import nltk; nltk.download('punkt')"
```

Make sure [Ollama](https://ollama.com) is installed and running locally with the model specified
in `config/config.py` (`LLM_MODEL = "llama3.2:latest"`):

```bash
ollama pull llama3.2
```

## Usage

**1. Add your PDFs** to `data/dataset/`.
**2. Build the index:**

```bash
python build.py
```

**3. Run the QA loop:**

```bash
python main.py
```

Type your question at the prompt, or type `exit` to quit.


## Configuration

All tunables live in `config/config.py`:

| Setting | Purpose |
|---|---|
| `CHUNK_SIZE`, `CHUNK_OVERLAP` | Controls chunk length (chars) and sentence-level overlap between chunks |
| `EMBEDDING_MODEL` | SentenceTransformer model used for dense embeddings |
| `DENSE_TOP_K` | Number of candidates pulled from the vector store per query |
| `DENSE_DISTANCE_THRESHOLD` | Max cosine distance allowed for a dense match to survive filtering |
| `RERANK_MODEL`, `RERANK_TOP_K` | Cross-encoder model and final result count after reranking |
| `RERANKED_SCORE_THRESHOLD` | Minimum rerank score required to keep a chunk |
| `LLM_MODEL`, `TEMPERATURE` | Local Ollama model and generation temperature |
